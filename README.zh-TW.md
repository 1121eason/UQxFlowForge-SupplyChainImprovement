# FlowForge｜供應鏈流程改善

**維修營運・庫存管理・逆向物流・Lean 分析・SAP Signavio・BPMN 2.0**

本專案以零組件維修與補給企業的營運流程為對象，評估如何在維持維修品質、庫存可追溯性與服務承諾的前提下，釋出承接更多客戶的營運能力。

分析範圍涵蓋需求接收、備品分配、內部維修、外包處理、出貨、退回及每日盤點。透過 AS-IS／TO-BE 建模、Lean 浪費分析、根因分析與量化情境，辨識五項營運問題，並提出七項相互連結的流程改善方案。

## 分析方法與專案成果

| 分析範疇 | 方法與產出 |
| --- | --- |
| 供應鏈與跨部門流程分析 | 區分資訊流、實物流、維修責任與外部合作方，釐清每筆案件、每日控制與跨日異常的邊界 |
| SAP Signavio／BPMN 建模 | AS-IS、TO-BE 各一個主流程與七個子流程，合計 16 張可瀏覽圖，保留 BPMN XML |
| Lean 與根因分析 | 八大浪費、五項問題、前三項優先排序，以及 Process／People／Policies／Systems 根因分析 |
| 量化分析與商業判斷 | 路由數量核對、工時與成本估算、維修期望時間、權重敏感度及掃描負擔的損益平衡 |
| 改善方案與落地規劃 | 七項改善逐一連結問題、流程位置、責任角色、保留控制與驗收條件 |

## 主要發現與改善決策

| 分析發現 | 量化依據或流程判斷 | 改善決策 |
| --- | --- | --- |
| 重複紀錄占用行政處理產能 | 選定的備品／外包出貨族群有 296 分鐘重複紀錄工時，依案例費率相當於 AU$740；整合紀錄情境估計可減少其中 266.4 分鐘，相當於 AU$666 | 以實際交接事件為共同資料來源，產生必要報表，保留完整性核對及失敗補救；效益需再扣除補救工作 |
| 維修升級處理增加資深技術人員負荷 | 完整重複作業情境下，從初次技術測試到放入待出貨托盤的期望時間為 74.40 分鐘；此範圍不含排隊、運輸與出貨等待 | 診斷證據足夠時採取精準處理，否則保留完整診斷；最終測試及重建後複測仍須執行 |
| 數位化效益取決於新增操作負擔 | 在既定控制縮減比例與作業量情境下，額外掃描每次約 13.15 秒即達損益平衡 | 優先在高風險移轉點試行，量測新增工時及資料可靠性，再決定是否縮減原有實體控制 |

上述為不同範圍的估算，不能直接相加。160 筆是到件族群的分析基準，不代表一天可以完成 160 筆維修；所有金額都不是已實現的現金節省。

## 改善設計

七項改善涵蓋出貨紀錄整合、已驗證退回資料再利用、資深技術人員的證據導向分流、作業現場狀態紀錄、出貨前實體庫存確認、結構化需求接收，以及緊急變更即時審查。各方案均連結至對應問題、BPMN 流程位置、責任角色與驗收條件，並保留必要測試、稽核、服務時限及人工例外處理。
